# Ride Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build active-ride passenger and driver chat with persisted history, websocket fanout, unread badge state, and Flutter tracking entry points.

**Architecture:** HTTP endpoints own validation and persistence while the existing realtime gateway fans out `ride_message` events to connected participants. Flutter reuses the tracking feature, extends the tracking websocket datasource for chat events, and adds a focused chat screen plus unread badge state without moving ride lifecycle logic into widgets.

**Tech Stack:** FastAPI, SQLAlchemy, Pydantic, Alembic, Flutter, Riverpod, websocket channels, pytest
